# Datasets

None of the raw data is committed to this repository. All three sources are
public; `scripts/download_data.sh` fetches them into this directory so that
each dataset keeps the licence and version of its provider.

```bash
./scripts/download_data.sh        # needs a Kaggle API token in ~/.kaggle/
```

| File (after download) | Rows | Size | Source |
|---|---|---|---|
| `bank_churn.csv` | 10,000 | ~0.7 MB | [Kaggle — Bank Customer Churn](https://www.kaggle.com/datasets/shantanudhakadd/bank-customer-churn-prediction) |
| `maven_bank_churn.csv` | 165,034 | ~12 MB | [Kaggle Playground Series S4E1](https://www.kaggle.com/competitions/playground-series-s4e1) |
| `cfpb_complaints.csv` | ~15.4 M | ~8.8 GB | [CFPB Consumer Complaint Database](https://files.consumerfinance.gov/ccdb/complaints.csv.zip) |

The CFPB file is the reason the data directory is not versioned: it is several
gigabytes on its own and is refreshed daily at source, so a committed copy
would be both oversized and stale.

## Pipeline outputs (`processed/`)

The pipeline writes its outputs here. Two classes of file are produced:

* **Metric tables (`*.csv`, a few kilobytes each) — committed.** These back
  every measured result in the dissertation, so the reported numbers can be
  checked without re-running anything:
  `cv_results_A.csv`, `cv_results_B.csv`, `cv_results_C.csv`,
  `fusion_table.csv`, `ood_metrics.csv`, `shap_top_hybrid.csv`,
  `table_4_*.csv`.
* **Bulk artefacts — not committed.** The embedding cache (`*.npy`), the
  sampled and enriched complaint corpora (`*.parquet`) and the serialised
  models (`*.joblib`) total several hundred megabytes and are regenerated by
  `scripts/run_all.sh`.

## Reproducing the reported results

```bash
python scripts/run_config_a.py                 # Table 9
python scripts/run_configs_BC.py               # Table 10
python scripts/run_complaint_features_fast.py  # fusion table, Figure 6
python scripts/run_hybrid_light.py             # Tables 11 and 12
python scripts/run_ood_validation.py           # Section 4.3.6
python scripts/run_shap_local.py               # Table 13, Figure 12
python scripts/run_result_figures.py           # Figures 10 and 11
```

Seeds are fixed (42, 123, 2024) and SMOTE is applied inside each
cross-validation fold, so repeated runs reproduce the published values.
## Two files that need a provenance note

**`table_4_7.csv` is superseded. Use `table_4_7_paired.csv`.** The older file
was written by `run_configs_BC.py` against an earlier Configuration C, and its
per-fold scores were not genuinely paired, so its significance verdicts do not
apply to the configuration that is now reported. `run_significance_tests.py`
cross-validates Configurations A and C over *identical* folds and writes
`table_4_7_paired.csv`, which is the table the dissertation reports and which
finds no significant separation. Both files are kept so the discrepancy is
visible rather than quietly resolved.

**`retention_eval_long.csv` carries no scores yet.** It holds 400 rows — 50
customer profiles, two message variants each, four raters — with the four
Likert columns deliberately empty. The rater panel has not been convened, so no
message-quality result is reported anywhere in this repository or in the
dissertation. `rating_key.csv` is the blinding key that maps each sheet position
back to the generic or LLM message. Once ratings are entered,
`scripts/score_retention_eval.py` produces the summary table and inter-rater
agreement.
